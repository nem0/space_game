# models/ - station asset pipeline

Everything here is generated by Python scripts that run in headless Blender (5.2). Nothing is hand-modelled: to change a model, edit its
script and re-run it. Meshes ship as **FBX only**. Engine: Lumix (`C:\projects\LumixEngine`), project root `C:\projects\space_game`.

The station is built from **modular kits in the damaged / salvaged style** (`concept_art/new_style.png`, `concept_art/central_new_style.webp`): small pieces on one shared
texture sheet that are assembled into modules in the engine. The earlier generation of one-FBX-per-module assets (`*_trim/`, `corridor/`, the wings, the dark `trim_sheet/`,
the first central module experiments) has been deleted together with its builders.
The game builds every module out of these pieces at run time: `scripts/modgen.evox` picks the parts (see "Generated modules" at the end).

## Run it

```bash
B="/c/Program Files/Blender Foundation/Blender 5.2/blender.exe"
cd /c/projects/space_game/tools
"$B" --background --python make_parts_sheet.py     # 1. the shared sheet -> parts_sheet/ (only when textures or the layout change, ~10 s)
"$B" --background --python build_parts_trim.py     # 2. habitat kit -> parts/ (~30 s)
"$B" --background --python build_central_kit.py    #    central module kit -> central_kit/ (~30 s; its demo borrows the antenna + dish from parts/parts_trim.blend)
```
Check the log for `... DONE`; a Python error prints a Traceback. Builders always rebuild from scratch and overwrite their own output folder.

## Files

| file | role |
|---|---|
| `tools/make_parts_sheet.py` | procedural 2048 sheet (numpy) -> `parts_sheet/textures/parts_{basecolor,normal,orm,emissive}.png`, `parts_sheet/parts_layout.json` |
| `tools/trim_lib.py` | low level: sheet lookup (`rect`, `SW`, `FIT`, `STRIP`), `Builder` (faces, boxes, revolved rings mapped onto the sheet), vertex AO bake, material, FBX export, sockets / collision helpers, preview render |
| `tools/parts_lib.py` | the kits' shared code: geometry helpers, habitat hull pieces, docking flange, attachments, `build_kit()`, `Demo` |
| `tools/build_parts_trim.py`, `tools/build_central_kit.py` | one kit each: the list of pieces and the demo layout |
| `parts_sheet/`, `parts/`, `central_kit/` | outputs |
| `earth/`, `earth_atmosphere/` | the planet (unrelated to the kits) |

Each kit folder contains one `<piece>.fbx` per piece (UV map `UV0` on the sheet, vertex colour layer `AO` with baked ambient occlusion, tangents exported), `parts_trim.mat`,
`demo_layout.json` (the demo assembly, Blender coordinates), a `.blend` of the final scene, a Cycles preview png and `manifest.json` (triangle counts, sizes).

## Conventions

- Units metres, Z up in Blender, FBX exported `axis_forward=-Z axis_up=Y` (Lumix). Blender (x, y, z) -> engine (x, z, -y).
- Sheet: 2048x2048, 512 px per metre. Regions are listed in `parts_layout.json` (`rects_xywh_from_top`, pixels, y from the top). Strips span the full width and tile
  horizontally; the builder maps a strip at sheet scale (`STRIP`), a decal by mapping the whole rect (`FIT`), a flat colour by sampling the centre of a swatch (`SW_*`).
  New regions: add to `LAYOUT` in `tools/make_parts_sheet.py` and **draw them after the existing code** (the RNG is seeded, earlier regions stay identical only then).
- Textures: `parts_basecolor` (sRGB), `parts_normal` (OpenGL, +Y up), `parts_orm` (R = cavity AO, G = roughness, B = metallic), `parts_emissive`.
- Lumix `.mat` (`standard.hlsl` slots in order: albedo, normal, roughness (.g), metallic (.b), ambient occlusion (.r), emissive x "Emission"): the packed ORM map fills slots 3-5.
  The template is `MAT` in `tools/parts_lib.py`. The editor writes a stub `.mat` when it first imports an FBX; the builder overwrites it. The FBX material name decides the file name.

## Gotchas learned

- The FBX exporter only writes an albedo texture when the image node feeds Base Color directly. The material has an AO multiply node for Blender previews;
  `link_base(mat, False)` before export, `link_base(mat, True)` before the preview render (`build_kit()` does both).
- Every face has its own vertices, so everything is flat-shaded. `Builder.face()` fixes the winding from the `out` vector: pass the intended outward normal.
- Vertex AO is a Python raycast (`ao_bake`, 28 rays, 0.5 m): it only darkens vertices, so large flat quads get little gradient (`patch()` subdivides plates for that reason).
- After a rebuild the engine may show stale cached meshes; give Studio ~15 s, or refresh the asset in the editor.

## Habitat kit (`parts/`, `tools/build_parts_trim.py`)
Look target: `concept_art/new_style.png` (warm white riveted plates, muted green / red / blue rings whose paint flakes down to the white primer, light steel double
ring frames with bolted clamp blocks, yellow rails, red cables, white equipment boxes, tanks, solar panels, dish). Before / after in Studio: `screenshots/style_now.png` (the first version of the kit),
`screenshots/style_new.png`, `screenshots/style_new_closeup.png`, `screenshots/style_new_port.png` (docking end).
```bash
"$B" --background --python make_parts_sheet.py     # own 2048 sheet -> parts_sheet/textures/parts_*.png + parts_sheet/parts_layout.json (~10 s)
"$B" --background --python build_parts_trim.py     # all parts -> parts/*.fbx, parts_trim.mat, demo_layout.json, preview (~30 s)
```
- One material `parts_trim` (`parts/parts_trim.mat`, written by the builder) + per-vertex AO in COLOR_0.
- Sheet regions (512 px/m): `HULL_WHITE` (4x2 plates of 0.5 m), `HULL_GREEN/RED/BLUE` (2x2), `HULL_SCRAP` (mismatched salvage plates with riveted patches); box faces `BOX`, `BOX_VENT`,
  `BOX_ELEC`, `CRATE`, `HATCH`, `SOLAR`, `HAZARD`, `BRACKET`, `GRILLE`; strips `RIB`, `GASKET`, `DOCK`, `DOCK_DARK`, `TANK_WHITE`, `TANK_BLUE`, `BEAM`, `FLANGE`; tube strips `RAIL`, `PIPE_YELLOW`,
  `CABLE_RED`, `CABLE_DARK` (U = along the tube, V = around it: use them with `hbar()`); swatches `SW_*`. Painting is layered (`Reg.paint`): bare metal, white primer, colour; a
  given fraction flakes off, mostly along plate edges. Emissive (x Emission 4 in the material) is used sparingly: `SW_LIGHT` (lamps, dock approach lights), `SW_WINDOW` (lit porthole glass on `hull_porthole_white` and `cen_wall_porthole`), `SW_LED_RED` (beacons on the central hubs), `SW_LED_GREEN`, and two status LEDs painted on `BOX_ELEC`. Free space: one 64 px swatch slot at x 1984, y 960.
- Tuned for the engine, not for Blender: the game sun is 3.5 with an ACES tonemap and no sky light, so (a) albedos authored at face value bleach to pastels - the `.mat` sets
  `Material color` to `GAIN` (0.62) and the paint colours in the sheet are deliberately greyer than they end up on screen; (b) metallic surfaces render black - everything in this
  sheet has metal <= 0.3. Always judge in Studio; the Blender preview is brighter and flatter.
- Hull segments: half cylinder R = 1.0 m, L = 1.0 m, axis X, centred on X (rotate 180 deg about X for the lower half; two halves = a ring; rings tile on 1 m).
  Variants: `hull_plain_{white,green,red,blue}`, `hull_basic` (torn hole, scrap plates, patches), `hull_window`, `hull_hatch`, `hull_porthole_{white,green}`, `hull_grille_red`, `hull_frame`,
  `hull_endclosed`, `hull_enddock` (0.6 m long: plated cone from R down to a 0.74 neck, a proud 0.80 steel flange with clamp lugs around its rim, bore stepping 0.50 / 0.44 / 0.38 deep into the hull, latch units, approach lights, grab rail, yellow hoop at the cone base). Shared hardware, identical on every segment so neighbours line up:
  ribs 5 cm inside each end (a joint reads as a double ring), clamp blocks at `STN` (9 stations) flush with the ends (two neighbours make one block), steel rails at 25 / 155 deg and
  yellow rails at 58 / 122 deg, cable lanes at 113 / 116.5 deg (red) and 31 / 35 deg. Portholes, tears and the grille sit at 140 deg; hatch and window on top (72..114 deg).
  Optional per variant: `loop` (yellow pipe ring), `wrap` (red cable wrapped around the hull).
- Attachments (stand on Z = 0): crate (two strapped cubes on a pallet), gastank (blue) / gastank_white, handrail, light, antenna, dish, vent, elec, solar (tilted on a tube frame), radar (slotted array tilted on a turntable).
- `ship_shuttle`: the mission shuttle, one piece. Origin on its dock face (the `dock_flange()` of `hull_enddock`, facing -X), body along +X: cabin with cockpit windows, saddle tanks, two solar panels, three engine bells. The Docking Hub (modgen `dockingHub()`) docks it at its +X end.
- Junction and wing pieces: `node_ports` (the two side ports of a junction in one piece: barrels along +-Y with dock flanges, faces 2.0 m from the hull axis; spawn it at the
  middle of a two-ring hull), `part_pad` (mounting pad, a unit bolts on 0.10 above it), `wing_mount` (0.5 m), `wing_boom`, `wing_solar`, `wing_solar_torn`, `wing_radiator`,
  `wing_radiator_torn` (1 m sections). Wing frame: origin on the mounting plate, +X away from the host, panels in the XY plane; a wing = mount + sections at x = 0.5, 1.5, 2.5.
- Helpers (all in `tools/parts_lib.py`, shared with the central kit; `tools/build_parts_trim.py` only lists the kit and the demo): `rev()` / `hrev()` (revolve with U at sheet scale; walk the profile with the outside on the left), `hbar()` (mitred tube along a polyline),
  `arc()` (tube around the hull), `faces()` (box maps), `shell()` (half-cylinder cells), `paint_uv()` (one random plate per 4x5 cells, optional `mix`).
- Damage rules: NO RUST. Damage = dents + soft buckling (analytic `Dmg`, continuous across surfaces), torn/peeled edges, patch plates, bent/sheared parts, flaked paint, vertex-AO grime.
- Check in Studio (remote plugin at http://127.0.0.1:17123/mcp, Studio auto-imports changed FBX / textures / .mat; give it ~15 s after a rebuild):
  `bash tools/parts_demo.sh spawn [--kit parts|central_kit] [--yaw DEG] [--pivot X] [--move X Z] [--lift M] [--sun DEG] [--only PREFIX] [--skip PART] [--nofill] [--noshadow]`
  destroys the previous demo entities and respawns `<kit>/demo_layout.json` (via `tools/gen_parts_demo.py`, run with Blender's bundled python - there is no system python); `bash tools/parts_demo.sh shot <name> [scale]` queues
  `make_screenshot` and converts the TGA to `screenshots/<name>.png` (`tools/tga2png.py`, also crops). The scene-view camera cannot be moved remotely and the user moves it,
  so turn the module (`--yaw`, about module x = `--pivot`, -0.5 = the dock end) and the sun (`--sun`) to suit the camera instead. The demo adds two shadowless point lights as earthshine / bounce fill; the game has its own
  planet light (four point lights in `scripts/orbit.evox`: blue earthshine from sunlit ground, orange glow from the burning night side).
- Studio glitch seen while iterating: after many rebuild + respawn rounds, thin black lines stayed in the scene near the world origin (y about -1..0). They are not in the meshes
  (bounding boxes are clean, no entities own them, they do not move with the module); `--lift 1.5` moves the demo clear of them, restarting Studio should remove them.
- Not done: LODs, collision, denser greebles (ladders, cargo nets, pipe runs, more clamp blocks), smooth shading of tubes (all faces are flat).

## Modular central module (`central_kit/`, `tools/build_central_kit.py`)
Look target: `concept_art/central_new_style.webp` (lens-shaped hub: band of coloured facets, solar roof, radiator underside, hubs with vents and masts, big ports).
Same sheet, material and rules as the habitat kit; Studio result: `screenshots/central_new.png`, Blender preview `central_kit/central_kit_preview.png`.
```bash
"$B" --background --python build_central_kit.py    # -> central_kit/*.fbx, parts_trim.mat, demo_layout.json, preview (~30 s); needs parts/parts_trim.blend for the demo's antenna + dish
bash tools/parts_demo.sh spawn --kit central_kit --yaw 320 --lift 1.0 --move 5.1 -2.2     # numbers suit where the scene camera was last left
```
- Shape: 16-sided lens. Band apothem 3.0 m, band height 1.5 m (z -0.75..0.75), shoulders, roof rising to the top hub (apothem 1.25, z 1.40), underside falling to the
  bottom hub (apothem 1.30, z -1.50); 3.5 m high without masts, 8 m across the ports. Constants at the top of the builder (`A`, `ZB`, `ST`, `SB`, `RI`, `UI`, `PORT_X`).
- **Placement rule:** every sector piece is built for the facet facing +X with its origin at the MODULE CENTRE. Put it at the module origin and turn it k * 22.5 deg about the
  vertical axis to put it on facet k. One wall + one roof + one underside piece per facet, plus the two hubs (whole pieces, no rotation needed).
- Wall pieces (interchangeable): `cen_wall_{white,green,red,blue,scrap}`, `cen_wall_{green,red,blue}_vent`, `cen_wall_porthole` (window + hung equipment box), `cen_wall_locker`,
  `cen_wall_panel`, and `cen_port`. Each wall brings half a post with clamp blocks at both edges (two neighbours make a full post), rim beams, yellow rim pipes and cable runs
  that meet the neighbours' at the corners.
- `cen_port`: a wall facet with a barrel (r 0.86) and the same docking flange as `hull_enddock` (`parts_lib.dock_flange()`); flange face 4.0 m from the centre, so a habitat's dock
  face meets it there. Ports can go on any facet: the demo follows the picture (ports on facets 0, 8 and 12, the porthole facet between them) although the concept's text says
  four ports at 90 deg - swap facet 4 for `cen_port` to get that.
- Roof pieces: `cen_roof_solar`, `cen_roof_vent` (short solar row + air handler near the hub), `cen_roof_plain`. Underside: `cen_under` (three dark radiator panels).
- Hubs: `cen_hub_top` (drum, railed deck, turret with vent faces; stand `part_antenna` / `part_dish` from the habitat kit on the turret at z = 2.02), `cen_hub_bottom` (drum, vent
  block, sensor mast).
- Not done: collision / LODs, a fourth port in the kit demo (the game's central module has all four),
  interior behind the porthole.

## Generated modules (`scripts/modgen.evox`)
The game has no per-module models. `modgen.generate(kind, seed)` fills `modgen.parts[0..count]` with kit parts (model path + module-local pose in engine space);
`build.spawn` creates one entity per part and `station_orbit.updateModules` poses them every frame (Evox cannot parent entities). The same seed gives the same module;
the game seeds from `core:random`, so every module built is different.
- Each kind has a fixed silhouette and a palette: cylindrical modules are `defs.rings(kind)` one-metre rings (battery and junction 2, greenhouse 5, the rest 3) with a
  `hull_enddock` at both ends, top / bottom half-rings drawn from the kind's hull palette (`topHull`, `bottomHull`) and equipment from `topItem` / `sideItem` / `underItem`.
  Equipment zones follow the kit: top deck (not on window / hatch rings), the 41 deg side, the underside at 238 / 302 deg.
- Docking Hub: two machinery rings, a work light and `ship_shuttle` as its last part, hidden while it has no shuttle (`build.syncShips`).
- Junction: two rings + `node_ports` + a `part_pad` above and below. Wings: `wing_mount` + three sections, outer ones sometimes torn. Gas storage: mount + boom + 3-4 tanks.
  Central module: 16 facets of random `cen_wall_*` / `cen_roof_*`, `cen_port` on every fourth facet, hubs, antenna and dish.
- **Ports are defined twice and must agree:** `defs.port()` / `defs.tip()` (game logic) and the layout in `modgen.evox` (what is drawn). Dock faces: cylinders at
  +-(rings / 2 + 0.6) on X, junction side ports at +-2.0 on Z and pads at +-1.12 on Y, central at +-4.0 on X and Z. Change a kit dimension -> change both.
- `put()` takes Blender coordinates and the kit's two rotations (rx about the hull axis, then rz about the vertical), so layouts can be copied from the kit builders' demos.
- Preview in Studio without running the game: `bash tools/parts_demo.sh module KIND SEED [--at X Y Z] [--yaw DEG] [--up|--down] [--keep]` (one module, `KIND` = index of
  `defs.kindFromIndex`), `bash tools/preview_station.sh X Y Z [SEED]` (a small station: central, five cylinders, junction, wing, gas storage) -> `screenshots/generated_station.png`.
- Changed with the move to kits: the central module has four docking ports and no wing pads (its own solar roof and radiators are counted in its stats: power 1.7, cooling 2.5),
  so the station no longer starts with wings; wings and gas storage need a junction pad. Modules are larger (dock face to dock face 4.2 m for a three-ring module).
